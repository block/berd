# Agent snapshot compatibility fixtures

`src/features/agents/agent-snapshot/fixtures/buzz-v1-config-only.agent.png`
was generated by Buzz's production `build_snapshot` + `encode_snapshot_png`
path from its `minimal_record()` test record. It is committed here so Berd's
test suite has no runtime or checkout dependency on Buzz.

To refresh after an intentional format change:

1. In a local Buzz checkout, add a temporary test beside the existing
   `managed_agents::agent_snapshot` tests that writes
   `encode_snapshot_png(&build_snapshot(&minimal_record(),
   MemoryLevel::None, vec![], None), None)` to the fixture path.
2. Run that one test with `BERD_COMPAT_FIXTURE` pointing at this file.
3. Remove the temporary Buzz test and confirm the Buzz checkout is clean.
4. Run:

   ```bash
   pnpm vitest run src/features/agents/agent-snapshot/pngCodec.test.ts
   ```

The test asserts semantic fields and secret-exclusion sentinels rather than
byte identity. Do not hand-author or re-encode this fixture in Berd.

`berd-v1-config-only.agent.png` was generated with Berd's production encoder
and decoded successfully by Buzz's production `decode_snapshot_png` function.
It is retained as the reverse-direction conformance artifact and intentionally
omits the optional `memory` field, matching Berd's configuration-only export
policy. In particular, Berd must insert the compatibility `tEXt` chunk before
the first `IDAT`; Buzz's PNG metadata reader does not discover a chunk inserted
after image data.
